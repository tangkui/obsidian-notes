
# 链表 vs 数组

## 内存结构图解

### 数组：连续内存
```
索引:  [0]    [1]    [2]    [3]    [4]
      ┌─────┬─────┬─────┬─────┬─────┐
      │  A  │  B  │  C  │  D  │  E  │   内存地址连续
      └─────┴─────┴─────┴─────┴─────┘
       ↑直接通过 arr[2] 访问 C
       
空间: |数据|数据|数据|数据|数据|  = 5 × 数据大小
```

### 链表：离散（分散）内存 + 指针
```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ val: A  │───→│ val: B  │───→│ val: C  │───→│ val: D  │───→ null
│ next: ──┘    │ next: ──┘    │ next: ──┘    │ next: null
└─────────┘    └─────────┘    └─────────┘    └─────────┘
  分散存储        分散存储        分散存储        分散存储

空间: |数据+指针| + |数据+指针| + |数据+指针| + |数据+指针|
      = 4 × (数据大小 + 指针大小)
```

## 核心区别一览

| 特性        | **数组 (Array)**       | **链表 (Linked List)**     |
| --------- | -------------------- | ------------------------ |
| **内存结构**  | 连续内存空间               | 分散内存，节点通过指针连接            |
| **访问方式**  | 随机访问 (Random Access) | 顺序访问 (Sequential Access) |
| **访问速度**  | O(1)                 | O(n)                     |
| **插入/删除** | O(n)                 | O(1)（已知位置时）              |
| **内存占用**  | 较少                   | 较多（需存储指针）                |
| **扩容**    | 困难，通常需要重新分配          | 灵活，动态分配                  |
| **缓存友好性** | 高（局部性原理）             | 低（节点分散）                  |

## 复杂度对比

### 时间复杂度

| 操作                          |      数组      |      链表       | 说明                    |
| --------------------------- | :----------: | :-----------: | --------------------- |
| **访问 (Access)**             |     O(1)     |     O(n)      | 数组通过索引直接计算地址          |
| **搜索 (Search)**             |     O(n)     |     O(n)      | 无序情况下都需要遍历            |
| **头部插入 (Insert at head)**   |     O(n)     |     O(1)      | 数组需移动所有元素             |
| **尾部插入 (Insert at tail)**   | O(1)* / O(n) | O(1) / O(n)** | *均摊；**单链表需遍历，双链表 O(1) |
| **中间插入 (Insert at middle)** |     O(n)     |    O(1)***    | ***已知前驱节点时            |
| **头部删除 (Delete at head)**   |     O(n)     |     O(1)      | 数组需移动后续元素             |
| **尾部删除 (Delete at tail)**   |     O(1)     | O(1) / O(n)** | **单链表需遍历找前驱           |
| **中间删除 (Delete at middle)** |     O(n)     |    O(1)***    | ***已知前驱节点时            |

### 空间复杂度

| 维度 | 数组 | 链表 | 说明 |
|------|:--:|:--:|------|
| **存储结构** | O(n) | O(n) | 都需要存储 n 个元素 |
| **额外空间** | O(1) | O(n) ~ O(2n) | 链表每个节点需 1-2 个指针 |
| **扩容开销** | O(n) | O(1) | 数组扩容需复制全部元素 |
| **内存碎片** | 无 | 有 | 链表节点分散，可能产生碎片 |
| **预分配** | 需要 | 不需要 | 数组通常需预分配或动态扩容 |

#### 空间细节分析

```text
【数组】
- 元素数据: n × sizeOf(element)
- 总空间: O(n)
- 特点: 连续分配，无额外开销

【单链表】
- 元素数据: n × sizeOf(element)
- 指针域:   n × sizeOf(pointer)  [32位4字节/64位8字节]
- 总空间:   O(2n) ~ 实际约为数组的 1.5-2 倍

【双向链表】
- 元素数据: n × sizeOf(element)
- 指针域:   2n × sizeOf(pointer)  [prev + next]
- 总空间:   O(3n) ~ 实际约为数组的 2-3 倍
```

## 代码示例对比

### 访问元素

```java
// 数组 - O(1) 时间, O(1) 空间
int x = arr[100];  // 基地址 + 100 × 元素大小

// 链表 - O(n) 时间, O(1) 空间（仅使用指针遍历）
Node node = head;
for (int i = 0; i < 100; i++) {
    node = node.next;
}
int x = node.value;
```

### 插入元素（中间位置）

**数组** - O(n) 时间, O(1) 额外空间（但可能触发 O(n) 扩容）
```java
// 插入到 index=2，后续元素后移
// [A][B][C][D] → [A][B][X][C][D]
// 最坏情况: 需要扩容并复制全部元素
```

**链表** - O(1) 时间（已知前驱）, O(1) 额外空间（新建节点）
```java
// newNode.next = prev.next;
// prev.next = newNode;
// 只需修改指针，无需移动数据
```

## 实际应用选择

| 场景 | 推荐结构 | 关键考量 |
|------|---------|---------|
| 频繁按索引查询 | **数组** | O(1) 访问，缓存友好 |
| 频繁头部插入/删除 | **链表** | O(1) 操作，无需移动 |
| 频繁尾部操作 | **数组** 或双向链表 | 数组均摊 O(1)，双链表 O(1) |
| 内存极度敏感 | **数组** | 无指针开销，空间紧凑 |
| 数据量动态变化大 | **链表** | 灵活扩容，无复制开销 |
| 实现 LRU Cache | **哈希 + 双向链表** | 结合两者优势 |
| 实现栈 (Stack) | **数组** | 操作简单，缓存友好 |
| 实现队列 (Queue) | **循环数组** 或双向链表 | 避免单链表尾部 O(n) |

## 现代计算机架构考量

> **缓存局部性原理 (Cache Locality)**

```text
CPU 缓存行通常为 64 字节

数组: [A][B][C][D][E][F]...  一次加载多个元素到缓存 ✓
链表: A(地址1000) → B(地址5000) → C(地址200) → ... 
      每次访问都可能缓存未命中 ✗
```

实际性能中，**数组往往比链表更快**，即使算法复杂度相同，因为：
- 缓存命中率高
- 预取 (Prefetch) 友好
- 无指针解引用开销

---

## 一句话总结

> **数组** 用 **空间连续性** 换取 **访问速度** 和 **缓存性能**；  
> **链表** 用 **访问速度** 和 **额外空间** 换取 **操作灵活性**。
